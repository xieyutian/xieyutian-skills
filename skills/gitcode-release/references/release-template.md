# 发行版描述模板

本文件定义 GitCode Release 描述的标准格式，Claude 根据收集的 git log 信息按此模板生成描述。

## 标准模板

```
## {tag_name} - {简要标题}

发布日期: {YYYY-MM-DD}

{如果存在新功能}
### ✨ 新功能

- {功能描述} @{作者}
{如果 commit 关联了 PR，附加 PR 编号}
- {功能描述} (#{PR编号}) @{作者}

{如果存在修复}
### 🐛 修复

- {修复描述} @{作者}

{如果存在改进/重构}
### 🔧 改进

- {改进描述} @{作者}

{如果存在其他变更}
### 📦 其他变更

- {变更描述}

{如果存在贡献者}
### 贡献者

感谢以下贡献者参与本版本开发: @{user1}, @{user2}

---

**完整变更**: {比较链接}
```

## 分类规则

基于 conventional commits 前缀将 commit 分类：

| 类别 | 匹配的前缀 | 模板章节 |
|------|-----------|----------|
| 新功能 | `feat:`, `feature:` | ✨ 新功能 |
| 修复 | `fix:`, `bugfix:`, `hotfix:` | 🐛 修复 |
| 重构 | `refactor:` | 🔧 改进 |
| 性能 | `perf:`, `performance:` | 🔧 改进 |
| 文档 | `docs:`, `doc:` | 📦 其他变更 |
| 测试 | `test:`, `tests:` | 省略（不体现在 Release 描述中） |
| 构建/CI | `build:`, `ci:` | 省略（不体现在 Release 描述中） |
| 其他 | 不匹配以上前缀 | 📦 其他变更 |

## 生成规则

1. **PR 编号提取**：从 merge commit 消息中提取，格式如 `Merge pull request #123` 或 `See pull request #123`
2. **作者信息**：从 commit 中提取作者名，同一作者只出现一次
3. **空类别省略**：如果某类别没有对应 commit，整个类别省略不显示
4. **简洁性**：每个条目不超过一行，去除 commit 前缀（如 `feat:`, `fix:`）
5. **去重**：过滤无实质意义的 commit（如 "wip", "fix typo", "update" 等过于简短的）
6. **比较链接**：使用 `{仓库URL}/compare/{上个tag}...{新tag}` 格式

## 示例输出

```
## v2.1.0 - 新增用户认证模块

发布日期: 2026-04-08

### ✨ 新功能

- 新增 OAuth2.0 登录支持 (#42) @zhangsan
- 添加用户角色权限管理 @lisi
- 新增 API 速率限制中间件 @zhangsan

### 🐛 修复

- 修复登录状态丢失问题 (#38) @wangwu
- 修复文件上传大小限制不生效的问题 @zhangsan

### 🔧 改进

- 优化数据库查询性能，列表查询提速 40% @lisi

### 贡献者

感谢以下贡献者参与本版本开发: @zhangsan, @lisi, @wangwu

---

**完整变更**: https://gitcode.com/owner/repo/compare/v2.0.0...v2.1.0
```
