# 代码审查清单

本文档包含完整的审查检查项，执行代码审查时必须逐项检查。

## 一、修改全面性和正确性审查清单

| 检查项 | 检查内容 | 说明 |
|--------|----------|------|
| [!] PR 描述对照 | PR 描述中声称修改的内容是否都已实现 | 修改全面性 |
| [?] 问题定位准确性 | 修复的问题是否是真正的问题 | Bug 修复类 PR |
| [+] 修改完整性 | 是否遗漏相关文件或代码路径 | 跨文件修改 |
| [*] 测试覆盖 | 是否包含必要的测试用例 | 功能开发类 PR |

**审查方法**：
- 对照步骤 4.5 中提取的「声称的修改点」，逐一验证是否在代码中实现
- **读取完整文件内容**，理解函数完整逻辑和上下文
- 检查是否有遗漏的边界情况或错误处理
- 验证修改逻辑是否正确解决了声称的问题

## 二、安全审查清单

### 核心原则

- **仅关注 PR 新引入的安全漏洞**，不评论代码库中已有的安全隐患
- **最小化误报**：仅报告置信度 >80% 的可利用漏洞，跳过理论性问题和风格问题
- **聚焦高影响**：优先关注可导致未授权访问、数据泄露或系统 compromise 的漏洞
- **仅报告新增问题**：仅报告本次 PR 变更中引入的安全问题

### 安全类别检查表

#### 输入验证漏洞 [SI]

| 检查项 | 具体漏洞类型 | 检查要点 |
|--------|-------------|---------|
| [SI-1] SQL 注入 | 未过滤的用户输入拼接 SQL | 参数化查询、ORM 使用是否正确 |
| [SI-2] 命令注入 | 系统调用/子进程使用未过滤输入 | `os.system`、`subprocess`、`exec` 等 |
| [SI-3] XXE 注入 | XML 解析接受外部实体 | XML 解析器配置、是否禁用外部实体 |
| [SI-4] 模板注入 | 模板引擎中使用用户输入 | Jinja2、Freemarker 等模板渲染 |
| [SI-5] NoSQL 注入 | NoSQL 查询中使用未过滤输入 | MongoDB 等查询构造 |
| [SI-6] 路径遍历 | 文件路径拼接使用用户输入 | `../` 穿越、路径规范化 |

#### 认证与授权问题 [SA]

| 检查项 | 具体漏洞类型 | 检查要点 |
|--------|-------------|---------|
| [SA-1] 认证绕过 | 认证逻辑缺陷 | 缺少认证检查、条件判断错误 |
| [SA-2] 权限提升 | 水平/垂直越权 | 角色检查、资源归属验证 |
| [SA-3] 会话管理 | 会话令牌安全 | Session ID 生成、过期策略 |
| [SA-4] JWT 漏洞 | Token 安全问题 | 签名验证、算法配置、密钥强度 |
| [SA-5] 授权逻辑绕过 | 权限检查不完整 | 中间件跳过、API 路径遗漏 |

#### 加密与密钥管理 [SC]

| 检查项 | 具体漏洞类型 | 检查要点 |
|--------|-------------|---------|
| [SC-1] 硬编码密钥 | API Key/密码/Token 硬编码 | `key = "xxx"`、`password = "123456"` |
| [SC-2] 弱加密算法 | 不安全的加密实现 | MD5/DES/RC4、ECB 模式 |
| [SC-3] 密钥存储不当 | 密钥管理缺陷 | 明文存储、不安全的配置文件 |
| [SC-4] 随机性问题 | 不安全的随机数 | 使用 `random` 而非 `secrets` |
| [SC-5] 证书验证绕过 | SSL/TLS 配置错误 | 禁用证书验证、`verify=False` |

#### 注入与代码执行 [SX]

| 检查项 | 具体漏洞类型 | 检查要点 |
|--------|-------------|---------|
| [SX-1] 反序列化 RCE | 不安全的反序列化 | `pickle.loads`、`yaml.load`、Java 序列化 |
| [SX-2] Eval 注入 | 动态代码执行 | `eval()`、`exec()`、`Function()` 构造 |
| [SX-3] XSS（反射型） | 用户输入直接渲染到 HTML | 未转义输出、内联脚本 |
| [SX-4] XSS（存储型） | 存储的恶意内容未过滤 | 数据库内容直接渲染 |
| [SX-5] XSS（DOM 型） | 客户端 DOM 操作 | `innerHTML`、`document.write` |

#### 数据暴露 [SD]

| 检查项 | 具体漏洞类型 | 检查要点 |
|--------|-------------|---------|
| [SD-1] 敏感数据日志 | 密钥/密码/PII 写入日志 | 日志内容检查 |
| [SD-2] PII 处理违规 | 个人信息泄露 | 数据收集、存储、传输合规性 |
| [SD-3] API 数据泄露 | 接口返回过多数据 | 响应字段过滤、分页 |
| [SD-4] 调试信息暴露 | 生产环境泄露调试数据 | 错误堆栈、配置信息输出 |

### 分析方法论

基于步骤 4 获取的 PR 上下文理解变更目的，基于步骤 3 的文件列表确定审查范围。

**Phase 1 - 仓库上下文研究**：
- 使用 Read 工具读取变更文件的完整内容（非仅 diff）
- 识别项目中已有的安全框架和库（如加密库、认证框架）
- 了解项目已有的安全编码模式和输入验证方式
- 识别项目的安全模型和威胁模型

**Phase 2 - 比较分析**：
- 对比 PR 变更与仓库已有代码的安全模式
- 识别偏离已有安全实践的变更
- 检查安全实现的一致性
- 标记引入新攻击面的代码

**Phase 3 - 漏洞评估**：
- 逐文件检查安全影响
- 追踪数据流：从用户输入到敏感操作
- 检查权限边界是否被安全跨越
- 识别注入点和不安全的反序列化

### 严重性与置信度指导

**严重性标准**：

| 级别 | 标准 | 示例 |
|------|------|------|
| **高** | 可直接利用的漏洞 | RCE、数据泄露、认证绕过 |
| **中** | 需要特定条件但影响重大 | 有前提条件的权限提升、需特定配置的注入 |
| **低** | 纵深防御或低影响漏洞 | 缺少安全加固措施、理论性风险 |

**置信度评估**：

| 置信度 | 标准 | 处理方式 |
|--------|------|----------|
| 0.9-1.0 | 确定的利用路径 | 必须报告 |
| 0.8-0.9 | 已知利用方法的明确漏洞模式 | 必须报告 |
| 0.7-0.8 | 需特定条件的可疑模式 | 可报告，标注条件 |
| <0.7 | 不确定 | **不报告** |

> 仅报告高和中严重性发现。宁可遗漏一些理论性问题，也不要用误报淹没报告。

### 误报过滤

**硬性排除项（不报告以下类型）**：

1. 拒绝服务（DOS）/ 资源耗尽攻击
2. 磁盘上受保护的密钥（由其他流程处理）
3. 限流/服务过载问题
4. 内存消耗或 CPU 耗尽
5. 非安全关键字段的输入验证问题（无实际安全影响）
6. 缺少安全加固措施（非具体漏洞）
7. 理论性的竞态条件或时序攻击（仅报告具体可利用的）
8. 过时第三方库漏洞（由单独流程管理）
9. 内存安全语言中的内存安全问题（如 Rust、Go）
10. 仅存在于测试文件中的漏洞
11. 日志欺骗（日志中输出未过滤用户输入）
12. 仅控制路径的 SSRF（SSRF 仅在控制 host/protocol 时报告）
13. AI 系统提示中的用户内容
14. 正则注入/ReDoS
15. 文档文件中的问题
16. 缺少审计日志

**先例规则**：

| 规则 | 说明 |
|------|------|
| 密钥日志 | 明文记录高价值密钥是漏洞；记录 URL 是安全的 |
| UUID 安全性 | UUID 可视为不可猜测，无需额外验证 |
| 可信来源 | 环境变量和 CLI 参数是可信值，攻击者通常无法修改 |
| 框架保护 | React/Angular 通常防 XSS，除非使用 `dangerouslySetInnerHTML` 等不安全方法 |
| 客户端权限 | 客户端 JS/TS 不需要权限检查，由服务端负责验证 |
| Shell 脚本 | Shell 脚本命令注入通常不可利用（一般不接受不可信输入） |
| Notebook 漏洞 | Jupyter Notebook 漏洞通常不可利用 |
| 日志内容 | 仅当日志暴露密钥、密码或 PII 时报告；非 PII 数据日志不是漏洞 |
| 低影响 Web 漏洞 | Tabnabbing、XS-Leaks、原型污染、开放重定向除非极高置信度不报告 |

## 三、代码质量审查清单

| 检查项 | 检查内容 | 常见问题示例 |
|--------|----------|------|
| [B] 逻辑错误 | 条件判断、循环边界、异常处理 | 边界条件遗漏、空指针、死循环 |
| [E] 性能问题 | 循环效率、内存使用、资源泄漏 | O(n^2) 循环、大对象未释放、连接未关闭 |
| [N] 命名规范 | 变量、函数、类的命名 | 单字母变量、误导性命名、风格不一致 |
| [CS] 代码结构 | 函数长度、嵌套深度、模块划分 | 过长函数、深层嵌套、职责不清 |
| [R] 可读性 | 注释、代码格式、逻辑清晰度 | 魔法数字、复杂表达式无注释 |
| [D] 重复代码 | 相似逻辑是否可提取 | 多处重复的代码片段 |
| [H] 错误处理 | 异常捕获、错误传播、降级策略 | 吞掉异常、错误信息丢失 |

**审查方法**：
- **使用 Read 工具读取完整文件**，理解代码上下文
- 对每个变更文件逐行审查，关注函数完整逻辑
- 对照上述检查项逐一确认
- 发现问题时记录文件路径、行号和代码片段

## 四、审查优先级

| 优先级 | 检查项 | 处理建议 |
|--------|--------|----------|
| **P0 必须修复** | [SC-1] 硬编码密钥、[SI-1] SQL 注入、[SI-2] 命令注入、[SA-1] 认证绕过、[SA-2] 权限提升、[SX-1] 反序列化 RCE | 阻塞合并，必须立即修复 |
| **P1 建议修复** | [SI-3~SI-6] 其他注入、[SA-3~SA-5] 会话/JWT/授权绕过、[SC-2~SC-5] 加密实现、[SX-2~SX-5] Eval/XSS、[SD-1] 敏感数据日志 | 可能影响安全，建议修复 |
| **P2 可选改进** | [SD-2~SD-4] 数据暴露、[B] 逻辑错误、[E] 性能问题、其他质量项 | 不阻塞合并，后续优化 |
